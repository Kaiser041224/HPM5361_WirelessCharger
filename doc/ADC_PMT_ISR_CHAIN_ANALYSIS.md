# HPM5361 ADC PMT 触发频率与 ISR 耗时实测分析

> 更新日期：2026-06-11
> 基于 RTT 诊断输出的实测数据

---

## 一、硬件环境

| 参数 | 值 |
|------|-----|
| MCU | HPM5361 RISC-V, 480MHz CPU |
| PWM 时钟 (mot0) | 120MHz |
| ADC 时钟 | 40MHz (div=3) 或 48MHz (div=5) |
| PWM 对齐 | 中心对齐 (CENTER) |
| TRGM 模式 | 上升沿脉冲 (`trgm_output_pulse_at_input_rising_edge`) |
| ADC 通道 | ADC0: 3ch (V_IN, I_COIL, I_LF) + 1ch dummy; ADC1: 3ch (V_LINK, I_L, I_IN) + 1ch dummy |
| ISR 隔离 | ADC0/ADC1 完全独立，无交叉处理，相同优先级 |

## 二、最终结论：根因与解决方案

### 2.1 根因

**ADC1 在 148kHz+200kHz 下丢失触发的根因是 PMT 回调内 `app_analog_signal_update_raw()` 的浮点换算 + 滤波导致 ISR 耗时过长。**

实测对比：

| ISR 内容 | ISR avg | ADC0 148kHz | ADC1 200kHz |
|----------|---------|-------------|-------------|
| DMA + 校验 + 浮点换算 + 滤波 + profiler | **1,531 ns** | 100% | **86.9%** |
| DMA + 校验 + raw 缓存 + profiler | **137 ns** | 100% | **100%** ✅ |

禁用滤波后 ISR 耗时降低 **91%**，ADC1 捕获率从 86.9% 提升到 **100%**。

### 2.2 解决方案

将 `app_analog_signal_update_raw()`（浮点换算 + 滤波）从 PMT 回调移到主循环：

```
ISR (137ns)                     主循环
┌──────────────────┐           ┌──────────────────────┐
│ PMT complete     │           │ app_analog_signal_   │
│ → DMA snapshot   │           │ process()            │
│ → validate       │    raw    │ → 读取 pmt_raw_cache │
│ → pmt_raw_cache  ├──────────→│ → 浮点换算           │
│ → profiler       │  (cache)  │ → 滤波               │
│ → return         │           │ → 更新 snapshot      │
└──────────────────┘           └──────────────────────┘
  137ns/次                       主循环频率
```

## 四、推测与依据

### 4.1 为什么 ISR 1531ns 会导致 200kHz 丢触发？

200kHz 触发间隔 = 5,000ns。ISR 平均 1,531ns，看似只占 30%。但：

1. **中断响应延迟**：从 PMT complete 到 ISR 第一条指令，PLIC 仲裁 + 上下文保存约 200-500ns
2. **ISR 尾部开销**：返回主程序 + PLIC 清 pending 约 100-200ns
3. **ADC0/ADC1 竞争**：两个 ISR 串行执行，总时间 ≈ 3,062ns
4. **最坏情况叠加**：当两个触发接近时，ADC0 ISR 阻塞 ADC1 响应，ADC1 的下一次触发到达时 ISR 仍未完成

实际每次中断总开销 ≈ 1,531ns + 500ns + 200ns = 2,231ns。
325k 次/秒 × 2,231ns = 725ms/s = 72.5% CPU。加上 PLIC 仲裁抖动和缓存未命中，接近 100%。

### 4.2 为什么禁用滤波后问题消失？

ISR 从 1,531ns 降到 137ns。实际每次中断总开销 ≈ 137ns + 500ns + 200ns = 837ns。
348k 次/秒 × 837ns = 291ms/s = 29.1% CPU。远低于 100%，无触发丢失。

### 4.3 为什么 ADC0 从不丢失？

1. **PLIC 优先级**：ADC0 和 ADC1 优先级相同（都是 1），但 ADC0 IRQ 号更小，HPM5361 PLIC 在同优先级下按 IRQ 号从小到大响应
2. **ADC0 触发间隔更长**：148kHz = 6.76μs，比 ADC1 的 5μs 有更大余量

## 六、诊断输出判据

| 字段 | 含义 | 正常值 |
|------|------|--------|
| `pmt Hz` | ADC 硬件 PMT complete 频率 | 应等于 PWM 触发频率 |
| `cb Hz` | 有效回调频率 | 应等于 pmt Hz |
| `ratio ADC1/ADC0` | 两路频率比 | 应等于 PWM1/PWM0 |
| `hits(+d,Hz)` | PROF 回调频率 | 应等于 pmt Hz |
| `out(+d)` | 超时（>10μs）次数 | 应为 0 或极小 |
